# Changes

Append-only, newest first, only durable changes. Three lines each: `Changed:`, `Why:`, `Forecloses:` (the door the change shuts).
Same convention as [ants `docs/changes.md`](https://github.com/p-to-q/ants/blob/main/docs/changes.md). A change that moves a surface between states also updates [surfaces.md](surfaces.md) in the same commit.

## 2026-10-17 · Name, positioning, colony mechanics and funding (0.0.2)
Changed: the project is named Blockwise ("A colony of trading agents you can fund, judged on-chain") and is no longer described as "ants on Monad"; ants is credited as the source of adapted mechanisms. Architecture gains §3a (layers by promotion, a nine-niche map of style × activity with an elite per niche, Thompson-sampling allocation on discovery rate with descendant credit and a floor, stagnation burst, tabu, path potential, honest controls, a ceiling proxy, diagnostics) and §3b (the testnet `Allocator` escrow: withdraw always works, steering only, suggested split, virtual return); the event contract gains `map` and `allocation`; contracts, benchmark (arms `evo_niche`, `global_elite`, `ceiling`), open questions 10a to 10d, roadmap (W8, issues 29 to 34, v0.9 real funds conditional), surfaces, presentation, FAQ, TUI and CLI follow; README (both languages), proposal and SECURITY are rewritten; decisions 0007 (revised) and 0008 added.
Why: the maintainer wants a system people can use, with ants-like automatic allocation of effort and no hand-written strategies, without claiming more than a testnet mechanism on a synthetic series can show.
Forecloses: calling it a desk, a proving ground or ants; separate resource pools per layer; a "facts" layer beyond results and lineage; an escrow with an owner, pause, proxy or oracle; real funds before a real market, settlement, an audit and risk limits; showing a virtual return without saying so; deploying the Allocator before its tests are green.

## 2026-10-17 · Repository framework, documentation set, draft contracts (0.0.1)
Changed: the repository is created with the layout in the README: Foundry project with three draft contracts (`Ledger`, `Evaluator`, `JudgeLog`; compile only), a pure TypeScript `packages/core` draft (spec, strategy mirror, seeded rng, series generator, event types), workspaces for chain, orchestrator and web (manifests only), and the documentation set: README (English and Chinese), proposal, principles (12), architecture (spec of record in §1, event contract in §5), Monad notes (measured / documented / assumed), Jev notes, presentation, roadmap with an issue backlog, glossary, surfaces, this file, CLI reference, terminal-interface manual, contract reference, open questions, benchmark protocol, operations, FAQ, data notes, and decisions 0001 to 0007. Governance files: CONTRIBUTING, AGENTS, SECURITY, CI workflow, PR and issue templates. The judge and ledger are on-chain; proposers, the bandit and any AI judge stay off-chain.
Why: several people will build this with the maintainer from today; they need one place that says what the system is, what is real, what is assumed and who may touch what, before more code exists.
Forecloses: a judge that runs on the proposer's machine, a score a proposer can write, a Monad claim without a status, a surface listed as working without a run that shows it, a global counter in the evaluation hot path (it would serialise the parallel demo), and any use of this repository against mainnet.
